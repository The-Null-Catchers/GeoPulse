# Signed webhooks

## Provisioning

Set `WEBHOOK_ENCRYPTION_KEY` to a Fernet key (generated by `scripts/init-env.py`) and `WEBHOOK_ALLOWED_HOSTS` to approved exact hostnames separated by commas. HTTPS and port 443 are required. Owners/admins create subscriptions in Developers → Webhooks or `POST /api/v1/webhooks`; the signing secret is returned once. Stored secrets are encrypted; protect the key separately from database backups. Changing the encryption key without re-encrypting stored secrets breaks delivery. Signing-secret rotation affects subsequent attempts, including pending retries; coordinate receiver configuration first.

Events: `device.online`, `device.offline`, `geofence.enter`, `geofence.exit`, `geofence.dwell`, `alert.created`, `alert.updated`, `trip.started`, `trip.completed`. Payloads include the stable outbox event ID, workspace and event data. They contain sensitive location information. Allowlist only receivers authorized to process it.

## Receiver verification

Read the exact request body bytes before JSON parsing. Compute HMAC-SHA256 using the once-issued signing secret and this concatenation:

```text
X-GeoPulse-Timestamp + "." + X-GeoPulse-Delivery + "." + body
```

Compare `X-GeoPulse-Signature` (`v1=` plus lowercase hex digest) in constant time. Reject stale timestamps (for example more than five minutes), persist delivery IDs for deduplication, and acknowledge only after durable acceptance. Each retry gets a fresh timestamp/signature but preserves the delivery ID and payload. Synchronize receiver clocks. Respond with any 2xx status to acknowledge.

## Durability and retries

Delivery rows are inserted transactionally during outbox processing. A dedicated worker claims rows using database leases and SKIP LOCKED; network I/O happens outside database transactions. Attempts and response status persist. Timeouts, connection failures, HTTP 408/429 and 5xx retry with exponential backoff (5, 10, 20, 40 seconds), up to five total attempts. Numeric Retry-After is honored up to one hour. Other 4xx and redirects fail without retry. Exhausted jobs remain failed for review. Explicit retry is allowed only for terminal deliveries with unused attempts and an enabled subscription.

Delivery history and attempts are administrator-only and workspace-isolated. Disabling cancels outstanding jobs; stale lease holders cannot overwrite cancellation. Job leases recover crashed workers. An expired lease can lead to duplicate delivery, so receiver deduplication is required. Delivery history is retained for 30 days. There is no outbound email integration.

## Network and privacy boundaries

The sender refuses credentials in URLs, unusual ports, fragments, control characters and destinations outside the exact allowlist. It resolves once, refuses any private/reserved address in the result, pins the validated numeric addresses and retains TLS hostname verification. Redirects and environment proxies are disabled. IPv4-mapped/transition address ranges are rejected. Receiver bodies and raw exception messages are not retained in attempt history.

Device-history erasure removes related delivery payloads and attempts. Disabling a hook or deleting history cannot recall a request already sent or delete data retained by a receiver. A paused worker must still be monitored: the Compose healthcheck checks its Redis heartbeat, and database delivery states expose failures/backlog. Use outbound firewall policy as additional infrastructure protection.

## Evidence

Automated tests use real PostGIS/Redis and a local TLS receiver with certificate verification and real HTTP requests. They exercise signed delivery, 503→204 retry, stable delivery IDs, redirect rejection, DNS pinning/private address refusal, workspace isolation, once-only secrets, rotation and history erasure. The local TLS resolver override is confined to tests; production never allows loopback destinations.
